# 飞书文档标签产品设计

> 状态：设计完成，尚未实现；2026-10-03。
> 技术方案：[飞书文档窗口技术设计](../tech/feishu-document-tabs-design.md)。
> 基础能力：[快速记录产品需求](quick-capture-notes-prd.md)。

## 1. 产品决定

在同一个贴贴便签窗口中提供“本地便签”和“飞书文档”两类标签。用户添加已有飞书文档链接，在应用中登录飞书，之后通过全局快捷键随时唤起并直接编辑。

本地便签继续适合快速、离线记录；飞书文档适合继续整理已有云端内容。两者共用标签入口、置顶和窗口控制，分别使用自己的编辑与保存方式。

第一版显示完整飞书网页，保存、权限、评论和协作以飞书页面为准。能否在目标租户中完整使用，须通过真实登录和编辑验收。

## 2. 能力状态与首版范围

| 状态 | 内容 |
| --- | --- |
| 当前可用 | 本地便签、Markdown、附件、窗口快捷键；飞书同步链接由系统浏览器打开 |
| 接口已预留 | 当前没有网页标签、应用内网页登录或网页视图控制接口 |
| 本次设计，尚未实现 | 添加飞书文档标签、窗口内访问和编辑、独立登录会话、页面保留、两类窗口尺寸 |
| 后续考虑 | 官方文档组件、更多网站、多账号空间、云端内容导回本地、跨设备标签同步 |

首版接受中国版飞书 `https://feishu.cn/docx/...`、租户子域名的 `/docx/...` 和 `/wiki/...` 链接。知识库链接直接交给飞书打开；只有其实际目标为可编辑文档且账号有权限时，才具备本设计的编辑体验。首版不承诺知识库内表格、多维表格等其他类型的完整能力，不使用应用凭证解析知识库目标。

## 3. 主要路径

### 3.1 添加已有文档

1. 打开顶部“标签”列表，选择“添加飞书文档”。
2. 粘贴链接，可选填写仅在贴贴便签显示的名称。
3. 校验格式后保存标签，切换到文档窗口；首次打开时加载页面。
4. 未登录时，用户在飞书页面完成登录；没有权限时，由飞书展示申请权限或只读界面。
5. 已登录且有编辑权限时，直接在原文档中输入。

添加面板说明：“登录有权限的飞书账号后可直接编辑。内容保存在飞书。”不要求填写 App ID、App Secret 或协作者邮箱。

相同主机、链接类型和文档标识的链接复用已有标签。分享参数不制造重复标签；知识库地址与其对应文档地址暂不自动合并。

### 3.2 从本地同步结果打开

本地便签已有飞书链接时，主入口“打开飞书文档”改为在贴贴便签内添加或激活对应标签；操作菜单保留“在浏览器打开”。

该操作只打开链接，不执行新一次同步、不把云端正文复制到本地，也不改变原便签的同步映射。若已有同步任务正在运行，打开动作不重启或取消任务。

### 3.3 快捷唤起和切换

- 唤起窗口恢复当前标签。本地便签聚焦编辑区；飞书标签聚焦网页，保留网页已有光标，不自动把光标移到文末。
- 顶部标签列表混合展示两种内容，以图标和类型文字区分。标签顺序固定，输入或切换不会重排；新标签追加到末尾。
- 切换离开本地便签前保存当前草稿，失败时留在原标签并提示重试。
- 切换离开飞书标签只隐藏页面，不刷新、不销毁，不声明飞书已保存。
- 全局“上一条 / 下一条”在混合标签中循环；设置文案改为“上一个标签 / 下一个标签”，已有快捷键配置继续有效。
- “新建便签”快捷键始终创建本地便签。`Escape` 关闭应用自己的菜单；网页获得焦点时保留飞书的 `Escape` 行为。

## 4. 窗口和布局

文档模式结构示意，尺寸为设计起点，不代表已经完成视觉验收：

```text
┌──────────────────────────────────────────────────────────────┐
│ 贴贴便签 · 项目周报              标签  置顶       最小化  隐藏 │
├──────────────────────────────────────────────────────────────┤
│ 飞书文档 · tenant.feishu.cn           刷新  放大  浏览器打开  ⋯ │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                      完整飞书网页                             │
│             登录、正文、工具栏、权限及保存提示                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

| 行为 | 本地便签 | 飞书文档 |
| --- | --- | --- |
| 首次尺寸 | 440×390 | 1000×720 |
| 常规最小尺寸 | 320×260 | 640×480 |
| 最大尺寸 | 延续 760×860 上限并适配屏幕 | 当前屏幕可用区域，保留边距 |
| 尺寸记忆 | 记住本地模式尺寸 | 所有飞书标签共用文档模式尺寸 |
| 主体 | 本地编辑器、预览、附件 | 完整网页 |
| 保存提示 | 本地保存状态 | 飞书页面自己的提示 |

- 尺寸以屏幕逻辑像素计；小屏幕优先保证窗口完整可见，必要时降低设计最小值。切换模式保留窗口位置，再夹紧到当前屏幕可用区域。
- 从隐藏状态唤起时，沿用当前“鼠标所在屏幕附近”的定位规则，避开菜单栏和 Dock / 任务栏。两类模式的上次尺寸分别保留。
- “放大”填充当前屏幕可用区域并保留边距；“还原”恢复文档模式放大前的尺寸。文档切换不改变放大状态。
- 置顶是窗口级设置，切换标签不改变。点击窗口关闭按钮只隐藏；失焦不隐藏整个窗口。
- 标签、添加面板和设置打开时，网页暂时隐藏，原位置显示中性背景；关闭面板恢复原页，避免菜单被网页挡住或点击穿透。不用页面截图替代背景。
- 应用语言切换只影响贴贴便签控件；飞书网页语言及主题由飞书自身控制。
- 文档工具栏显示当前页面的真实域名，登录期间随跳转更新；不显示包含认证参数的完整地址。

## 5. 登录、保存和数据边界

### 登录

同一台机器上的贴贴便签飞书标签共用一个登录会话，独立于系统浏览器和飞书客户端。首次可能需要重新登录；会话有效期由飞书决定，重启后尽量复用，失效后在网页重新登录。

第一版支持一个共享会话，不提供同时登录不同账号的标签。设置中的“清除飞书网页登录”影响全部飞书标签，执行前提示用户检查保存状态。此操作不删除标签、不清除本地便签或 API 同步配置，也不宣称退出其他设备的飞书账号。

### 内容和状态

- 本地只保存飞书文档的链接、显示名称和标签配置。网页运行时可能产生浏览器缓存，这不构成离线副本或本地备份。
- 飞书标签没有本地附件、Markdown 预览、“同步到飞书”或本地“已保存”标志。原网页里的上传等操作按飞书自身交互执行。
- 应用只能准确显示“正在加载页面”“页面加载失败”等状态；页面加载完成不等于登录成功、拥有编辑权限或内容已保存。
- 本地便签仍能手动同步。对同一远端文档的本地写入继续走原有文档或章节冲突检查；浏览页面不更新已确认版本号，不自动合并或覆盖。

### 隐藏、关闭与重启

| 操作 | 页面处理 | 标签处理 |
| --- | --- | --- |
| 隐藏窗口 / 最小化 / 切换标签 | 保留已加载页面 | 保留 |
| 刷新 | 重新加载当前文档 | 保留 |
| 关闭页面 | 卸载当前页面，释放资源 | 保留，下次激活再加载 |
| 从贴贴便签移除 | 卸载页面 | 移除本地入口，飞书文档不删除 |
| 退出应用 | 正常结束全部页面 | 保留，下次只加载当前标签 |

刷新、关闭页面、移除已加载标签、清除登录和退出应用会结束页面使用，需要提示检查飞书保存状态，并尊重网页的离开确认；取消当前页面卸载后，该页面保留。不在每次隐藏或切换时提示，不把延迟几秒作为保存成功的证据。

清除登录或退出涉及多个页面时，先统一提示，再逐页正常关闭。中途取消即停止后续关闭和清除 / 退出；之前已经关闭的页面仍保留标签，可重新加载，但不承诺恢复其原有光标和临时输入。

标签可以保存多份链接；首版最多同时保留 5 个已加载飞书页面。这是待实测调整的资源预算。打开第 6 个时提示先关闭一个页面，提供已加载列表，不静默卸载旧页；关闭页面后入口仍保留。

应用重启恢复标签和上次选中项，飞书登录可能继续有效；不承诺光标、滚动位置和未保存输入跨重启恢复。保留页面期间的光标与滚动位置也以飞书实际行为为准。

## 6. 异常体验

| 情况 | 行为 |
| --- | --- |
| 链接格式不支持 | 留在添加面板，说明支持的链接类型，不创建空标签 |
| 网络错误或加载超时 | 保留标签，提供重试和在浏览器打开；加载超时提示不主动销毁页面 |
| 登录失效、只读、无权限、文档已删除 | 保留飞书原页提示，不用应用自造状态替代 |
| 企业 SSO 或登录弹窗尚不兼容 | 明确说明暂不能在应用内完成，允许打开原文档到系统浏览器 |
| 网页崩溃 | 显示恢复入口，不静默刷新；无法保证恢复未保存输入 |
| 页面跳往其他网站 | 留在原文档，显示目标域名并由用户选择是否在浏览器打开 |
| 标签配置写入失败 | 显示失败并保留可重试界面，不报添加或移除成功 |
| 已加载页面达到上限 | 提示关闭一个页面后再打开，已有页面继续运行 |

## 7. 首版验收

1. 无 API 同步配置时也能添加飞书标签，并进入真实登录流程。
2. 在用户指定的测试文档内，由用户完成登录、输入和飞书保存确认；在另一个客户端重新打开验证内容。
3. 编辑后立即隐藏、切到本地再切回，页面不被主动重载；输入法、粘贴、光标和滚动表现符合实际操作预期。
4. 重启后标签存在；验证有效会话复用和失效后的重新登录，不把这项与光标恢复混为一谈。
5. 本地便签与文档切换恢复各自尺寸；小屏、多屏、置顶、最小化和放大还原可用。
6. 标签菜单和设置完整可见、可点击，网页不遮挡控件；网页焦点下快捷键能正确切换。
7. 无权限、断网、加载失败和崩溃可恢复；不会显示虚假的“已保存 / 已同步”。
8. 从同步结果打开复用标签；网页中的更改仍能触发原有同步冲突检查。
9. 移除入口不删除远端文档；清除网页登录不清除本地内容和 API 凭证；页面上限不引发静默卸载。

## 8. 实施顺序

先验证独立网页视图中的真实登录、编辑、保存和隐藏恢复，再实现标签持久化及混合切换，最后补齐异常恢复、登录清理和回归验收。原型验证不通过时先修正方案，不把“能显示登录页”当作编辑能力完成。
