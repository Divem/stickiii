# 独立便签窗口使用与验收

## 当前可用

主窗口的更多菜单提供“独立窗口打开”，便签列表每行也有独立打开图标。已独立打开的便签有状态标记，重复打开会恢复并聚焦已有窗口。

主窗口的便签列表按钮与底部页码单击展开搜索列表，再次点击关闭。macOS 主窗口通过 `acceptFirstMouse` 接收失焦后的首次点击；菜单内不可聚焦区域和菜单触发按钮不触发失焦关闭，外部点击、焦点移到其他控件、Escape 和窗口失焦继续关闭列表。

列表搜索框自动聚焦。macOS WebKit 在鼠标按下便签行时可能先让搜索框失焦，且没有下一焦点；若此时关闭列表，随后的点击就会丢失。列表行在左键按下时保留搜索焦点，按钮的点击继续负责切换历史便签或独立打开；面板也不会把没有下一焦点的失焦误判为离开面板。回归检查覆盖 A/B 历史便签切换，以及搜索框失焦后从列表独立打开。

独立窗口可以编辑 Markdown、切换预览、添加附件、更换便签主题、置顶、最小化，使用已配置的 AI 和飞书同步。设置菜单中提供便签主题及“主窗口设置”；凭据与快捷键只在主窗口配置。

同一便签只由一个窗口编辑：独立打开后主窗口显示预览和“前往窗口”。关闭独立窗口先保存，便签仍保留；“回到主窗口编辑”保存后关闭独立窗口，并定位主窗口中的对应便签。主窗口隐藏不影响独立窗口，全局快捷键仍操作主窗口。

正常退出时等待所有窗口保存成功，并记录仍打开窗口的尺寸、位置和置顶状态。下次启动恢复这些窗口，关闭的窗口不再恢复；断开显示器后将窗口移回可见工作区。任何窗口保存失败都会取消退出并保留草稿，可点击“重试保存”后重新退出。

## 方案与实现

- [独立便签窗口方案](../tech/independent-note-windows.md)
- Rust 窗口与编辑归属：`src-tauri/src/note_windows.rs`、`lib.rs`。
- 共用界面：`src/renderer/NoteEditor.tsx`；窗口上下文和具名操作通过 `desktop.ts` 接入。
- 正文沿用 `notes.json`；窗口状态单独写入 `note-windows.json`。窗口打开、关闭和恢复不改变便签的修改时间。
- 通知在指定 WebView 内派发，避免全局监听收到其他窗口的正文或关闭请求。独立窗口读写、附件和飞书任务均校验原生登记的归属。

## 验收与复现

在 macOS arm64 使用隔离 QA 应用标识、数据目录与凭据命名空间运行真实 WKWebView；不会连接已安装应用或修改真实便签。运行：

```bash
npm run test:window-smoke
```

命令构建独立 QA debug 二进制，创建三条测试便签，先执行并行窗口测试，正常退出后再启动一次检查恢复；超时只终止该命令自己启动的 QA 进程。结果保存在命令打印的临时目录 `qa-result.json`。

macOS 另用一个临时 QA 窗口取得焦点，再向隔离应用发送一次原生鼠标点击，验证置顶且失焦时单击能展开列表并聚焦搜索框。辅助进程只定位本次启动的 QA PID，不操作已安装应用；需要运行终端已有系统事件投递权限，缺少权限时明确失败，不主动弹出授权。菜单回归还覆盖焦点移回触发按钮后的单次开关、菜单内不可聚焦区域、菜单切换、外部点击和 Escape。

已验证：每条便签只读到自己的数据、主窗口旧草稿写入被拒绝、重复打开复用窗口、三条便签分别打开、独立编辑与预览、关闭保存失败保留草稿、主窗口刷新、删除前保存最新输入、返回主窗口定位最新内容、其他窗口不受关闭影响、多窗口退出失败取消并可重试、正常退出后的窗口与置顶恢复、恢复窗口的编辑归属和删除。

独立窗口的既有运行记录见 [验收记录](independent-note-windows-validation.json)。包含列表交互检查的最新运行结果以脚本打印的临时目录 `qa-result.json` 为准。

历史便签切换与列表独立打开的失焦回归、自动检查和 macOS 打包检查见 [列表点击修复验收](note-list-click-validation.json)。

## 验收边界

Windows WebView2 构建与实际运行尚未验收；Windows 单独运行自动与实机检查后才能报告通过。本次检查未执行真实 AI 服务或飞书远端写入，独立窗口沿用已有认证、传输与结果校验，真实服务需配置测试凭据后单独验收。

窗口恢复以正常保存、退出为前提。异常终止或系统强制杀进程的未保存草稿恢复日志仍尚未实现。签名、公证和安装包发布不属于本次开发验收。
