# 截图粘贴、图片链接预览与文件拖入

## 当前可用

- 在主窗口或独立便签的正文中按 `Command/Ctrl + V`，将剪贴板中的截图或图片插入正文。编辑时显示一行图片文件名链接，图片前后可以继续输入 Markdown 文字；预览时按相同顺序显示完整图片。支持 PNG、JPEG、GIF、WebP、BMP；普通文字仍按原有方式粘贴。如果剪贴板同时带有文字与图片，优先保留文字粘贴。
- 将一个或多个文件拖入便签正文区域：可导入时显示“松开以添加附件”与虚线提示，松开后导入当前便签。编辑与预览模式都支持；在预览模式粘贴图片时，先让正文获得焦点。
- 一次最多粘贴或拖入 20 个附件，单个不超过 20 MiB（界面简写为 20 MB）。逐个导入，超限或失败的文件不会阻止其他文件；部分失败时保留已成功导入的附件并提示失败数量。现有文件选择器的大小限制不作变更。
- 导入期间显示“正在添加附件”，仍可继续输入和切换便签；附件归属于开始导入时的原便签，合并时保留其最新文字、主题和同步信息，并立即保存。暂不能再次导入或删除便签；独立窗口的关闭、回到主窗口与退出等待导入及保存完成。
- 图片按编辑光标位置插入正文，预览模式或文件选择器导入的图片追加到正文末尾。编辑模式的链接高 28 px，长文件名单行省略；鼠标悬停或键盘聚焦时显示最多 280×200 px 的浮动预览，按窗口边缘调整位置、不撑开正文，图片完整等比例显示且小图不放大。鼠标移开、焦点离开、Escape、滚动、窗口缩放/失焦或切换到预览模式时收起。点击链接打开原图，悬停或键盘聚焦时显示移除按钮。预览模式仍按正文可用宽高缩小居中，为上下文字及间距预留约 96 px。普通文件仍使用底部附件列表。旧便签中的图片附件自动显示在正文末尾，不会只因打开而改写存储。无名称或通用 `image.png` 的剪贴板图片生成带时间的文件名。
- 一屏适配针对单张图片。较长正文或多张图片仍按正文顺序滚动；只调整显示尺寸，不裁剪图片、不改变原文件，也不缩小正文字号。
- 3 MiB 以内的图片沿用已保存的预览；更大的图片在编辑链接悬停/聚焦或进入预览模式后从受管附件目录读取，最多 20 MiB。加载中与读取/解码失败分别显示明确状态，失败时仍可打开原图。
- 主窗口中的独立便签预览不接受附件导入，需前往其编辑窗口。设置面板、正在切换、退出或转移编辑归属期间不接受新的导入。拖到正文以外会提示正确的放置区域，并阻止文件替换应用页面。

## 安全与保存设计

沿用已经关闭原生拖放处理的 WebView 配置，由浏览器提供用户粘贴/拖放产生的 `File`。主窗口 `dragDropEnabled: false` 与独立窗口 `disable_drag_drop_handler()` 无需修改；HTML 拖放在 Windows 上需要关闭原生处理，见 [Tauri 配置说明](https://v2.tauri.app/reference/config/#dragdropenabled)。

`desktop.ts` 的 `importAttachment(noteId, file, imageOnly)` 是唯一新增桌面方法。它通过 `FileReader` 读取用户提供的文件，先检查大小，再发送名称、Base64 内容和便签 ID；不发送外部文件路径，也不提供任意文件读取、剪贴板轮询或文件系统插件能力。

Rust 的 `import_attachment` 在导入前后检查可信本地来源、原生窗口注册和便签编辑归属，拒绝已删除的便签。存储层检查编码与解码后的大小、文件名和图片格式标识，以 UUID 命名写入应用附件目录，临时文件 `fsync` 后原子替换；图片 MIME 依据字节标识，而非渲染层传入的类型。字节标识只用于格式分类，不保证损坏图片能正常显示。

独立窗口的新附件登记进该窗口的 `imports` 集合，保存继续通过已有附件归属检查。复制期间归属改变或便签删除时，拒绝返回并清理刚写入的文件。渲染层合并最新草稿，所有保存继续经过 `NoteSaveQueue`；保存失败保留附件草稿和重试入口，不提示保存成功。

正文保存 `![图片名称](attachment:附件ID)`，图片文件继续留在本地附件目录。编辑器只将独占段落且属于当前便签的本地图片引用渲染为图片链接，代码块内的示例保持源码；文字区域保存原始 Markdown。浮动预览通过 Portal 放在页面顶层，避免正文滚动容器裁切。切换编辑和预览继续保留正文位置。删除图片时同时移除其正文引用和附件记录。导入期间的新输入全部保留；若光标前的文字已经改动，图片追加到末尾，避免猜测位置或覆盖新输入。

`attachment_preview(noteId, attachmentId)` 只接受两个 ID。命令检查可信来源、原生窗口登记与便签归属，再由存储层从已保存便签查找附件、验证受管路径、读取限量字节并根据实际字节确认图片格式；渲染层不能提供任意文件路径。同步时沿用同一附件归属校验，Rust 读取受管字节并通过 `docx_image` 或 `docx_file` 素材接口上传；图片二进制不写入 Markdown，网络图片仍以链接同步。
