# 截图粘贴与文件拖入

## 当前可用

- 在主窗口或独立便签的正文中按 `Command/Ctrl + V`，将剪贴板中的截图或图片添加为本地附件。支持 PNG、JPEG、GIF、WebP、BMP；普通文字仍按原有方式粘贴。如果剪贴板同时带有文字与图片，优先保留文字粘贴。
- 将一个或多个文件拖入便签正文区域：可导入时显示“松开以添加附件”与虚线提示，松开后导入当前便签。编辑与预览模式都支持；在预览模式粘贴图片时，先让正文获得焦点。
- 一次最多粘贴或拖入 20 个附件，单个不超过 20 MiB（界面简写为 20 MB）。逐个导入，超限或失败的文件不会阻止其他文件；部分失败时保留已成功导入的附件并提示失败数量。现有文件选择器的大小限制不作变更。
- 导入期间显示“正在添加附件”，仍可继续输入和切换便签；附件归属于开始导入时的原便签，合并时保留其最新文字、主题和同步信息，并立即保存。暂不能再次导入或删除便签；独立窗口的关闭、回到主窗口与退出等待导入及保存完成。
- 图片与文件沿用底部附件列表，可打开和移除。3 MiB 以内的支持图片提供缩略预览；更大的图片保留附件卡片，可通过系统打开。无名称或通用 `image.png` 的剪贴板图片生成带时间的文件名。
- 主窗口中的独立便签预览不接受附件导入，需前往其编辑窗口。设置面板、正在切换、退出或转移编辑归属期间不接受新的导入。拖到正文以外会提示正确的放置区域，并阻止文件替换应用页面。

## 安全与保存设计

沿用已经关闭原生拖放处理的 WebView 配置，由浏览器提供用户粘贴/拖放产生的 `File`。主窗口 `dragDropEnabled: false` 与独立窗口 `disable_drag_drop_handler()` 无需修改；HTML 拖放在 Windows 上需要关闭原生处理，见 [Tauri 配置说明](https://v2.tauri.app/reference/config/#dragdropenabled)。

`desktop.ts` 的 `importAttachment(noteId, file, imageOnly)` 是唯一新增桌面方法。它通过 `FileReader` 读取用户提供的文件，先检查大小，再发送名称、Base64 内容和便签 ID；不发送外部文件路径，也不提供任意文件读取、剪贴板轮询或文件系统插件能力。

Rust 的 `import_attachment` 在导入前后检查可信本地来源、原生窗口注册和便签编辑归属，拒绝已删除的便签。存储层检查编码与解码后的大小、文件名和图片格式标识，以 UUID 命名写入应用附件目录，临时文件 `fsync` 后原子替换；图片 MIME 依据字节标识，而非渲染层传入的类型。字节标识只用于格式分类，不保证损坏图片能正常显示。

独立窗口的新附件登记进该窗口的 `imports` 集合，保存继续通过已有附件归属检查。复制期间归属改变或便签删除时，拒绝返回并清理刚写入的文件。渲染层合并最新草稿，所有保存继续经过 `NoteSaveQueue`；保存失败保留附件草稿和重试入口，不提示保存成功。

## 验证

2026-10-03：`npm run typecheck`、72 项 `test:contracts`、`check:native`、29 项 `test:native`、macOS `test:window-smoke` 和生产 `build` 通过。浏览器模拟桌面桥验证了导入期间继续输入并切换便签、部分失败保留成功附件、超限拒绝、拖放提示及 320×260 无横向溢出。生产构建存在 Vite 的单块超过 500 kB 提示，不影响构建成功；未生成安装包或替换已安装应用。

- 前端契约覆盖纯图片/文字/混合剪贴板、超限、部分失败、顺序导入、继续输入及切换便签后的合并、删除保护与具名字节导入桥。
- Rust 测试覆盖文件字节落盘、受管路径、空文件、无效编码、路径式文件名、大小限制、非图片粘贴与删除保护。
- macOS 隔离窗口测试通过 DOM 构造图片粘贴及预览模式文件拖放，实际调用 Rust 写入并读取便签；覆盖主窗口与独立窗口，以及独立窗口跨便签导入拒绝、主窗口向独立编辑便签导入拒绝、退出与重启。
- 上述 DOM 事件测试不等于系统剪贴板与 Finder/资源管理器手动操作验收；Windows 运行仍需在 Windows 完成。
