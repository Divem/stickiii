# 独立便签窗口方案

## 目标与交互

每条本地便签可以在独立的桌面窗口中显示、编辑、预览、添加附件、使用 AI 和飞书同步。主窗口仍负责便签库、新建、删除与全局设置。便签内容只有一份，独立打开不创建副本。

- 当前便签的更多菜单和便签列表提供“独立窗口打开”。重复打开恢复并聚焦已有窗口。
- 独立窗口固定显示一条便签，省去新建、列表及翻页；保留预览、置顶、最小化、关闭和便签操作。
- 一条便签只允许一个编辑入口。打开前等待该便签的操作及保存完成，独立打开后主窗口改为预览并提供“前往窗口”。关闭独立窗口后恢复主窗口编辑。
- “回到主窗口编辑”保存后关闭独立窗口，并选中主窗口中的对应便签。
- 主窗口关闭仍为隐藏，不影响独立窗口。关闭独立窗口先保存，失败则保留窗口和草稿。
- 每个窗口独立置顶。正常退出时记住仍打开的窗口及其位置、尺寸和置顶状态，下次启动恢复；关闭的窗口不恢复。断开显示器后，将窗口移回可见工作区。
- 删除已独立打开的便签需先由该窗口完成保存与正在执行的操作，再关闭窗口并删除。失败保留便签。
- 全局快捷键继续针对主窗口。退出应用需要所有窗口保存成功；任一失败取消退出并恢复编辑。

## 原生窗口与数据边界

Rust 创建所有窗口，并维护不向 renderer 开放修改的窗口 label 与便签 ID 映射。窗口上下文由原生层提供，不能依据 renderer 的 URL 参数或自行提供的便签 ID 授权。

`main` 保留便签库和全局配置权限。独立窗口只能读取、保存和执行其绑定便签的操作，不能列出其他便签、创建其他便签、修改快捷键或凭据。附件读取需同时满足应用管理目录与当前便签附件归属。飞书任务必须校验创建窗口与任务归属。远程页面仍无业务命令权限。

所有保存提交在 Rust 校验编辑归属之后，通过已有的原子存储执行。打开、关闭和删除与保存遵循一致锁顺序；窗口之间通过定向通知更新主窗口预览，避免把其他便签内容广播给独立窗口。来自本窗口的保存通知不覆盖本地正在输入的草稿。

便签内容继续保存在 `notes.json`，窗口状态单独保存到 `note-windows.json`，不改变正文修改时间。窗口恢复只针对仍存在的便签。

## 前端与退出协议

主窗口和独立窗口复用便签编辑界面与保存队列，根据原生窗口上下文显示管理或单便签模式。语言、透明度通过同源偏好设置同步；独立窗口中的全局设置入口定位主窗口。

退出请求带唯一 ID，Rust 收集主窗口和所有独立窗口的保存确认。renderer 锁定编辑，等待附件、AI、同步结束并 flush 草稿。只有全部确认成功且窗口布局落盘成功才退出；失败通知所有窗口取消退出，过期确认不能完成新一轮退出。

## 验收

- 同一便签重复打开复用窗口，多条便签可以分别编辑，主窗口及时显示保存后的内容。
- 主窗口和其他独立窗口不能保存已交给另一窗口编辑的便签。
- 关闭、回主窗口、删除和退出均保存最新输入；保存失败保留草稿和可重试入口。
- 正常退出后恢复打开的窗口，关闭的窗口不恢复；窗口恢复不修改便签时间。
- 隔离数据的原生烟测验证真实 WebView、IPC、存储与窗口生命周期；macOS 与 Windows 分别记录运行验收，真实外部写入单独验收。
